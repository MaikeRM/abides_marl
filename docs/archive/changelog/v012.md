# Changelog

## v0.1.2 - 2026-02-16

### Added
- **Interface ABC para agentes** (`app/agents/base.py`): Nova estrutura de classes para suportar agentes RL.
  - `Agent` agora é ABC com métodos abstratos: `wakeup`, `receive`, `get_observation`, `get_reward`
  - Nova classe `HeuristicAgent` com implementação padrão para agentes heurísticos
  - Métodos adicionais: `reset()`, `get_info()`, `compute_pnl()`
  - Propriedades herdadas: `position`, `cash`, `pnl_history`

### Changed
- **Otimização do Order Book** (`app/agents/exchange.py`):
  - Substituição de listas por heaps (`heapq`) para O(log n) no melhor preço
  - `_order_map` para O(1) em cancelamentos por order_id
  - Propriedades `bids` e `asks` retornam listas ordenadas sob demanda

- **Refatoração de agentes**:
  - `InformedTrader`, `LiquidityTrader`, `NoiseTrader`, `MarketMakerAgent` agora herdam de `HeuristicAgent`
  - Remoção de atributos duplicados (`position`, `cash`) - agora vêm da classe base

- **Correção do MarketMakerAgent** (`app/agents/market_maker.py`):
  - Substituição de `cancel_all` por cancelamento específico por `order_id`
  - Novo atributo `pending_orders` para rastrear ordens ativas

### Fixed
- **Ordenação price-time priority no matching**: O algoritmo de matching agora garante ordenação correta por preço e timestamp no livro de ofertas.

  O problema original era que o `heapq` do Python não garante ordenação completa por timestamp quando preços são iguais - apenas garante que o menor/maior elemento está no topo. Isso causava ordens com timestamps diferentes (e mesmo preço) a não serem processadas na ordem correta de chegada.

  A correção adiciona `heapq.heapify()` após cada modificação no heap para reorganizar completamente os elementos e garantir a propriedade de price-time priority:
  - Para asks: menor preço primeiro, e para preços iguais, menor timestamp
  - Para bids: maior preço primeiro, e para preços iguais, menor timestamp

### Changes
- `app/agents/exchange.py`:
  - Linha 155: Adicionado `heapq.heapify(opp)` no início do loop de matching para garantir ordenação completa antes de cada iteração
  - Linhas 212-213: Adicionado `heapq.heapify(opp)` após execução parcial de ordem resting (quando `resting.qty > 0`)
  - Linhas 218-222: Adicionado `heapq.heapify()` após inserção de novas ordens limite ao livro
  - Linhas 130, 136: Adicionado `heapq.heapify()` após cancelamento de ordens

### Plano de correção pré-Fase 1 (hardening v0.12.x)

Objetivo: estabilizar `ExchangeAgent` e alinhar baseline de release antes da implementação da **Fase 1 - Formalização de agentes (v0.2.0)**.

#### 1) Corrigir crash no heap por empate completo de prioridade
- Problema: quando duas ordens têm mesma prioridade no heap (ex.: mesmo preço e `ts`), o Python tenta comparar `Order` e lança `TypeError`.
- Ação:
  - Introduzir chave de desempate estável no heap (ex.: `order_id`) para evitar comparação direta de objetos.
  - Padronizar tuplas do livro para manter ordenação determinística por preço-tempo-id.
- Resultado esperado: simulação não quebra em cenários de alta concorrência de ordens.

#### 2) Corrigir vazamento lógico em `_order_map`
- Problema: ordens totalmente executadas/agressoras podem permanecer no `_order_map` mesmo não estando no book.
- Ação:
  - Registrar no `_order_map` apenas ordens resting (que de fato entram no livro), ou
  - Remover explicitamente do mapa toda ordem agressora totalmente consumida após `_match`.
  - Garantir invariantes: `len(_order_map)` deve refletir ordens ativas em `_bids + _asks`.
- Resultado esperado: sem crescimento indevido de memória e sem cancelamentos inconsistentes.

#### 3) Restringir cancelamento por propriedade da ordem
- Problema: `CANCEL_ORDER` por `order_id` não valida dono da ordem.
- Ação:
  - Em `_handle_cancel`, permitir cancelamento apenas se `order.agent_id == msg.src`.
  - Opcional: registrar log/retorno de tentativa inválida para observabilidade.
- Resultado esperado: isolamento entre agentes e integridade do livro.

#### 4) Reverter regressão de performance causada por `heapify` no loop
- Problema: chamadas repetidas de `heapq.heapify()` dentro do loop de matching reintroduzem custo O(n).
- Ação:
  - Remover `heapify` redundante no caminho quente.
  - Confiar em `heappush`/`heappop` para manter propriedade de heap.
  - Aplicar `heapify` apenas em operações de remoção arbitrária (cancelamento por índice).
- Resultado esperado: matching volta ao custo esperado e melhora throughput da simulação.

#### 5) Alinhar versionamento e comunicação de release
- Problema: `pyproject.toml` está em `0.1.0`, enquanto documentação/changelog já evoluíram para `v0.12` e preparação para `v0.2.0`.
- Ação:
  - Definir estratégia de semver única para repo e pacote.
  - Atualizar `pyproject.toml` e referências em README/changelog para consistência.
- Resultado esperado: rastreabilidade clara entre código, pacote e documentação.
- **Status: ✅ RESOLVIDO** - Versionamento unificado para v0.2.0

#### 6) Corrigir inconsistência de baseline no runner
- Problema: comentário diz "2 Market Makers", mas código instancia 5.
- Ação:
  - Ajustar comentário para refletir configuração real, ou reduzir para 2 se esse for o baseline desejado.
- Resultado esperado: documentação interna coerente com experimento executado.

#### Validação planejada (após as correções)
- Sanidade: executar simulação longa e verificar ausência de `TypeError`.
- Invariantes do book: validar consistência entre `_order_map` e ordens resting.
